Rules:
1. Keep clips contiguous, ordered, and fully covering the source text.
2. Segment by directing beats, not by raw length. First understand the whole story arc, then split at changes in dramatic function.
3. For generic story videos, fairy tales, narrative shorts, and story ads, prefer 4-8 clips: world setup, inciting event, action/help, emotional reaction, magical/object payoff, time passage, thematic ending. Very short stories should still be split into at least 3 beats unless they contain only one simple action.
4. Do not collapse a complete story into one giant clip. Do not over-split one sentence into beatless fragments.
5. Each clip must contain a complete director task: action goal, emotional state, and result. Good summaries should name that function, such as "night forest setup and rabbit introduction" or "firefly falls into puddle and triggers rescue".
6. The summary must also state the production function of the clip: setup, trigger, progression, reaction, reversal, transition, or closure.
7. Prefer boundaries at time jumps, location changes, new character/prop entrances, goal changes, conflict/incident, emotional turns, and before theme statements.
8. `source_anchor` must be a phrase from inside the start/end span.
9. `info_points` should list only source-supported story, asset, or action facts; do not write judgments.
10. `reasoning` explains boundary choice and production use only; it must not add plot, and `production_function` must match the summary.
11. location, characters, and props should prefer exact names from libraries when possible and include only assets visible or used in that clip.
12. These fields must be sufficient for downstream asset setup, storyboard generation, voice matching, and export readiness checks; do not include entities that are only mentioned but never visible.
13. For short-drama production, keep one continuous same-location action or one dialogue exchange in the same clip whenever possible. Do not split one line and its reaction across clips.
14. In ordinary stories or fairy tales, props are story objects, such as a leaf, moon lamp, puddle, key, or letter. Do not turn them into product selling points.
15. Only product, brand, platform, or ad prompts should treat props as merchandise or commercial display objects.
16. If the prop library is empty but the story contains a visible recurring object, use the stable source-text name for that object. If no visible prop appears, return [].
17. Return JSON only, no markdown or extra text.
