# 剧本级视频转绘功能工作计划

## 0. 背景与竞品流程抽象

竞品流程可抽象为：

```text
视频 → 源剧本 → 目标剧本
```

对应任务步骤：

```text
1. 视频反译：从视频中反推出源剧本，支持分集并行。
2. 设定提炼：从源剧本中提炼人物、世界观、场景、风格等设定总纲。（人工检查点）
3. 逐集对齐：将视频内容与源剧本逐集、逐段、逐镜头对齐。（人工检查点）
4. 目标设定：基于用户目标，生成目标设定总纲。（人工检查点）
5. 逐集转绘：根据源剧本、目标设定和对齐关系，生成目标剧本。
```

因此，本功能不应被理解为单纯的“视频滤镜”或“视频风格化”，而应被定义为：

> 将原视频反译为结构化源剧本，再基于目标设定生成目标剧本，并为后续图像/视频生成链路提供可编排输入。

## 1. 产品边界

### 1.1 功能定位

剧本级视频转绘是一个“视频理解 + 剧本重写 + 生成编排”的中间层能力。

产出可被后续生成链路消费的目标剧本、分镜、角色设定、场景设定和任务计划。

### 1.2 输入

| 输入项 | 说明 |
|---|---|
| 原视频 / 多集视频 | 用户上传或从已有资产中选择的视频 |
| 转绘目标描述 | 用户希望转成的题材、风格、时代、人物关系、世界观等 |
| 保留策略 | 保留剧情结构、人物关系、镜头节奏、动作、对白、场景中的哪些部分 |
| 输出粒度 | 剧本级、分集级、场景级、分镜级 |

### 1.3 输出

| 输出项 | 说明 |
|---|---|
| 源剧本 | 从视频反译得到的结构化剧本 |
| 源设定总纲 | 从源剧本提炼的人物、场景、世界观、叙事结构 |
| 视频-剧本对齐结果 | 视频时间轴、分集、场景、镜头与剧本文本之间的映射 |
| 目标设定总纲 | 用户目标风格下的新人物、新世界观、新场景设定 |
| 目标剧本 | 基于源剧本和目标设定生成的新剧本 |

### 1.5 非目标

本功能第一阶段不应承担以下责任：

| 非目标 | 原因 |
|---|---|
| 直接生成最终视频 | 容易把功能做成不可控的大链路 |
| 保证电影级一致性 | 需要角色库、LoRA、参考图、视频模型稳定性共同支持 |
| 替代现有视频生成链路 | 应作为上游编排输入，而不是另起系统 |
| 任意长度视频全自动处理 | 成本、耗时、失败恢复都不可控 |

## 2. 涉及对象

### 2.1 核心业务对象（后续设计数据模型字段）

#### VideoRedrawProject

表示一次剧本级视频转绘项目。

#### SourceVideo

表示用户输入的原始视频资产，可以是单集，也可以是多集。

#### SourceScript

表示从视频反译得到的源剧本。

#### SettingBible

表示设定总纲。可分为源设定总纲和目标设定总纲。

#### AlignmentMap

表示视频与剧本之间的对齐关系。

#### TargetScript

表示最终生成的目标剧本。

#### RedrawTask

表示剧本级视频转绘中的异步任务。

### 2.2 任务类型

| 任务类型 | 说明 |
|---|---|
| VIDEO_REVERSE_SCRIPT | 视频反译，视频转源剧本 |
| SOURCE_SETTING_EXTRACT | 源设定提炼 |
| VIDEO_SCRIPT_ALIGN | 视频与源剧本对齐 |
| TARGET_SETTING_GENERATE | 目标设定生成 |
| SCRIPT_REDRAW | 源剧本转目标剧本 |
| HUMAN_CHECK | 人工检查点 |
| EXPORT_RESULT | 导出目标剧本或后续生成任务 |

### 2.3 资产对象

建议复用现有 Asset 体系，不要为转绘单独设计一套文件系统。

## 3. 状态设计

### 3.1 项目状态

```text
CREATED
UPLOADING
READY
RUNNING
WAITING_CHECK
SUCCEEDED
FAILED
CANCELED
```

| 状态 | 含义 |
|---|---|
| CREATED | 项目已创建，尚未上传或选择视频 |
| UPLOADING | 视频上传中 |
| READY | 输入已准备好，可以开始转绘 |
| RUNNING | 至少一个任务正在执行 |
| WAITING_CHECK | 等待用户检查或确认 |
| SUCCEEDED | 全流程完成 |
| FAILED | 流程失败且无法自动恢复 |
| CANCELED | 用户主动取消 |

### 3.2 单任务状态

```text
PENDING
QUEUED
RUNNING
WAITING_CHECK
SUCCEEDED
FAILED
RETRYING
CANCELED
SKIPPED
```

### 3.3 检查点状态

```text
UNCHECKED
CHECKING
APPROVED
REJECTED
REGENERATING
```

| 检查点 | 检查内容 |
|---|---|
| 设定提炼检查 | 源设定总纲是否准确 |
| 逐集对齐检查 | 视频片段与源剧本是否对齐 |
| 目标设定检查 | 目标世界观、角色、风格是否符合用户意图s |

### 3.4 推荐状态推进

```text
CREATED
→ READY
→ VIDEO_REVERSE_SCRIPT_RUNNING
→ SOURCE_SETTING_EXTRACT_RUNNING
→ WAITING_SOURCE_SETTING_CHECK
→ VIDEO_SCRIPT_ALIGN_RUNNING
→ WAITING_ALIGNMENT_CHECK
→ TARGET_SETTING_GENERATE_RUNNING
→ WAITING_TARGET_SETTING_CHECK
→ SCRIPT_REDRAW_RUNNING
→ SUCCEEDED
```

## 4. 相关操作

### 4.1 用户操作

| 操作 | 说明 |
|---|---|
| 创建转绘项目 | 新建一个视频转绘项目 |
| 上传/选择原视频 | 选择已有视频资产或上传新视频 |
| 填写转绘目标 | 描述目标题材、风格、人物、世界观等 |
| 设置保留策略 | 选择保留剧情、人物关系、镜头节奏、动作、对白等 |
| 启动视频反译 | 从视频生成源剧本 |
| 检查源设定 | 查看并修改源设定总纲 |
| 检查对齐结果 | 查看视频片段与剧本段落的对应关系 |
| 检查目标设定 | 确认目标总纲是否符合预期 |
| 启动逐集转绘 | 生成目标剧本 |
| 重新生成 | 对某一步输出不满意时重新生成 |
| 局部编辑 | 手动修改设定、剧本或对齐结果 |
| 导出结果 | 导出 Markdown、JSON、分镜任务或进入视频生成链路 |

### 4.2 系统操作

| 操作 | 说明 |
|---|---|
| 解析视频元信息 | 获取时长、分辨率、fps、编码格式 |
| 分集/分段 | 按集、场景、镜头或时间片拆分 |
| 抽帧 | 抽取关键帧用于视频理解 |
| 视频反译 | 调用多模态模型生成源剧本 |
| 设定提炼 | 从源剧本中提取角色、世界观、场景、风格 |
| 对齐计算 | 建立视频时间轴与源剧本结构的映射 |
| Prompt 构造 | 根据源剧本和目标设定生成转绘 prompt |
| 剧本转绘 | 生成目标剧本 |
| 任务调度 | 入队、执行、重试、取消 |
| 状态更新 | 推进任务和项目状态 |
| 结果保存 | 保存结构化结果和资产文件 |
| 日志记录 | 记录 task_id、模型、耗时、失败原因 |

### 4.3 管理操作

| 操作 | 说明 |
|---|---|
| 查看任务队列 | 查看待执行、执行中、失败任务 |
| 手动重试 | 对失败任务重新执行 |
| 手动跳过 | 对非关键任务跳过 |
| 查看模型调用日志 | 排查生成失败或质量问题 |
| 成本统计 | 统计每个项目的模型调用成本 |
| 清理中间资产 | 清理抽帧、临时 JSON、中间结果 |

## 5. 最小链路

### 5.1 MVP 主链路

```text
用户创建项目
→ 上传原视频
→ 填写目标转绘描述
→ 系统解析视频
→ 系统反译源剧本
→ 系统提炼源设定总纲
→ 用户检查源设定
→ 系统生成目标设定总纲
→ 用户检查目标设定
→ 系统生成目标剧本
→ 用户查看 / 编辑 / 导出目标剧本
```

### 5.2 对应竞品步骤映射

| 竞品步骤 | 本系统 MVP 实现 |
|---|---|
| 视频反译 | 视频 → 源剧本 |
| 设定提炼 | 源剧本 → 源设定总纲 |
| 逐集对齐 | 视频片段与剧本段落的基础映射 |
| 目标设定 | 用户目标 + 源设定 → 目标设定总纲 |
| 逐集转绘 | 源剧本 + 目标设定 → 目标剧本 |

### 5.3 最小后端链路

```text
POST /video-redraw/projects
→ 创建项目

POST /video-redraw/projects/{id}/videos
→ 上传或绑定原视频

POST /video-redraw/projects/{id}/start
→ 创建主任务和子任务

Worker 执行：
1. VIDEO_REVERSE_SCRIPT
2. SOURCE_SETTING_EXTRACT
3. TARGET_SETTING_GENERATE
4. SCRIPT_REDRAW

GET /video-redraw/projects/{id}
→ 查询项目状态、任务状态、结果

POST /video-redraw/tasks/{taskId}/retry
→ 重试失败任务

POST /video-redraw/checkpoints/{checkpointId}/approve
→ 用户确认检查点
```

### 5.4 最小数据链路

```text
source_video_asset
→ source_script_json
→ source_setting_bible_json
→ target_setting_bible_json
→ target_script_json / target_script_markdown
```

## 6. 工作拆解

### 阶段一：调研与现有系统梳理

目标：明确可复用链路。

任务：

```text
1. 跑通现有视频生成主链路。
2. 梳理现有 Project / Asset / Task / Provider / Worker / Queue 模块。
3. 确认现有系统是否已有分镜、剧本、场景、角色对象。
4. 确认已有任务状态机和前端进度展示方式。
5. 画出现有链路图。
```

输出：

```text
现有链路图
可复用模块列表
需要新增的对象和接口列表
```

### 阶段二：MVP 数据模型与接口设计

目标：将视频转绘接入现有项目和任务系统。

任务：

```text
1. 新增或扩展 VideoRedrawProject。
2. 新增 RedrawTask 类型。
3. 新增 SourceScript、SettingBible、TargetScript 等结果对象。
4. 设计任务状态机。
5. 设计项目查询接口和任务重试接口。
```

输出：

```text
数据模型草案
接口草案
状态机草案
```

### 阶段三：跑通最小生成链路

目标：完成“视频 → 源剧本 → 目标剧本”的闭环。

任务：

```text
1. 实现视频上传或绑定已有视频。
2. 实现视频反译任务。
3. 实现源设定提炼任务。
4. 实现目标设定生成任务。
5. 实现剧本转绘任务。
6. 保存中间结果和最终结果。
7. 前端展示任务进度。
```

输出：

```text
可运行 MVP
一次完整转绘 demo
失败重试能力
```

### 阶段四：加入人工检查点

目标：让用户可控地推进关键步骤。

任务：

```text
1. 在设定提炼后加入检查点。
2. 在目标设定后加入检查点。
3. 支持用户编辑设定后继续生成。
4. 支持重新生成当前步骤。
```

输出：

```text
检查点机制
设定编辑能力
重新生成能力
```

### 阶段五：增强逐集/逐段能力

目标：支持多集或长视频。

任务：

```text
1. 支持分集任务。
2. 支持按时间片或场景拆分。
3. 支持分集并行处理。
4. 支持部分失败重试。
5. 支持逐集结果合并。
```

输出：

```text
分集并行处理能力
部分失败恢复能力
多集目标剧本导出能力
```

## 7. 优先级建议

### P0：必须完成

```text
1. 接入现有任务系统。
2. 创建视频转绘项目。
3. 视频反译为源剧本。
4. 源设定提炼。
5. 目标设定生成。
6. 目标剧本生成。
7. 任务状态展示。
8. 失败重试。
```

### P1：建议完成

```text
1. 人工检查点。
2. 设定编辑。
3. 目标剧本编辑。
4. 分集并行。
5. 基础视频-剧本对齐。
```

### P2：后续增强

```text
1. 分镜级对齐。
2. 自动进入视频生成链路。
3. 角色一致性控制。
4. 风格一致性检查。
5. 多版本对比。
6. 成本统计和质量评估。
```

## 8. 关键风险

| 风险 | 表现 | 应对 |
|---|---|---|
| 任务失败难恢复 | 中间步骤失败导致全链路重跑 | 每一步结果持久化，支持局部重试 |
| 资产膨胀 | 抽帧和中间文件过多 | 设计临时资产清理策略 |
