# FrameOS 无限画布 Bundle 与运行时证据

审计日期：2026-07-17  
审计对象：本地 FrameOS App 当前版本的无限画布运行时，以及无限画布前端 bundle、主应用 bundle、无限画布 CSS 与 3D 导演台 bundle  
用途：为 NoriVideo 的 FrameOS 画布复刻建立可复查的原版能力基线，并修正 `canvas-gap-audit.md` 中缺少原版证据时做出的推断

2026-07-18 复核：当前 App 加载的画布入口已更新为 `InfiniteCanvasView-Bqj6Xjpj.js`。该文件与本文取证的 `InfiniteCanvasView-PnZlPY4Z.js` 字节数相同；将 Vite 依赖资源文件名中的 8 位内容哈希归一化后，两份主画布代码逐字节一致。因此本文的画布业务、交互和 API 结论仍适用于当前运行版本，变化仅来自依赖资源指纹重建。

## 1. 结论与证据边界

静态分析确认，FrameOS 原版并非只有基础节点编辑器。Bundle 中能找到以下完整模块链：

- 项目级多画布、增量操作、revision 冲突、本地离线缓存与退避重试。
- 文本、图片、视频、音频、3D 模型的持久节点生成与刷新后任务恢复。
- 图片改图、宫格切分、局部聚焦、超清、720 全景、视频去字幕、故事版等派生处理。
- 多选、框选、成组、排列、自动布局、系统剪贴板、工作流模板与多层右键菜单。
- 独立的 3D 导演台文档、场景编辑、角色姿势、机位、截图暂存和回传画布。

首次进入画布时曾短暂出现以下异常：

```text
ReferenceError: Cannot access 'Xi' before initialization
    at InfiniteCanvasView-PnZlPY4Z.js
```

同日后续复测时原版画布已正常渲染，`Xi` 异常不再复现；因此它只能保留为一次历史启动异常，不能继续作为“原版画布当前空白”或“无法运行时验证”的结论。恢复后已在以下深链完成只读探索：

```text
#/canvas/01KTZGXBAAD7JVTJTZJMC0RME4/01KXP38HVYXH7JFK2P32HDV01G
```

运行时已验证新增节点入口、文本/图片/视频/3D 模型生成配置、3D 导演台、分组排列和全局整理等界面与交互分支。为保护 FrameOS 云端数据，本次没有创建、生成、保存、上传、重命名或删除，因此仍需区分“运行时已打开/操作到配置态”和“真实写入或生成端到端成功”。

结论边界：

1. 原版画布当前能够正常进入和交互，先前 `Xi` 异常不是当前阻塞项。
2. 本文标为“运行时已验证”的能力已经在当前 App 中实际打开或切换；写操作和生成结果仍未验证。
3. 仅在 Bundle 中存在的模块仍可能受账号权限、服务端配置、模型配置、feature flag 或死代码影响。
4. 不能依据本文声称 NoriVideo 已经完成 FrameOS 无限画布的 1:1 复刻。

### 1.1 状态词定义

| 状态 | 本文含义 |
| --- | --- |
| 运行时已验证 | 当前 App 中实际打开、切换或观察到该界面/交互分支；不自动等同于写请求或生成任务成功 |
| Bundle 中存在 | 能在当前 bundle 中找到组件、事件、API、数据变换或清晰文案链；未必已在当前 UI 成功操作 |
| 当前开关关闭 | 功能代码存在，但当前主组件传入的常量或条件明确阻止入口显示 |
| 本次未发现 | 在本次限定的画布相关 bundle 和关键字范围内没有找到证据；不是对所有 FrameOS 版本的绝对否定 |
| 写入未验证 | 为保护云端数据，没有提交创建、生成、保存、上传、重命名或删除请求 |
| 交互未验证 | 当前运行时探索没有逐动作点击、拖拽或完成对应后端调用 |

## 3. 路由与模块组成

主应用使用 hash 路由；实际地址表现为 `#/canvas`。路由表明确注册：

- `/canvas`，页面标题“无限画布”。
- `/canvas/:projectId/:canvasId`，项目和画布深链。
- 两条路由都异步加载 `InfiniteCanvasView-PnZlPY4Z.js`。

证据：`index.pretty.js:31544-31555`。

主画布 bundle 还动态加载或引用：

- `CanvasStudio3dEditor`：3D 导演台。
- `MaterialPickerDialog`、`MaterialLibraryPanel`：素材选择与素材库。
- `ToolboxMentionInput`：提示词中的媒体引用。
- 图片、视频、音频、3D 模型工具箱模型配置。
- 角色、物品、环境、分镜、剧集与工作流 service。

这说明画布并不是孤立的纯前端白板，而是与项目、素材库和生成服务共同工作的项目级创作界面。是否所有 service 在当前账号下可访问，交互未验证。

## 4. API、文档与同步模型

### 4.1 API 基址与接口

主应用以 `/api/canvas` 创建画布 API client。证据：`index.pretty.js:4125`。

| 方法与相对路径 | Bundle 中的用途 | 状态 |
| --- | --- | --- |
| `GET /list` | 按 `project_id` 获取画布列表 | Bundle 中存在 |
| `POST /create` | 创建画布和初始 `canvas_meta` | Bundle 中存在 |
| `GET /detail` | 获取画布文档与 revision | Bundle 中存在 |
| `POST /update` | 更新画布标题 | Bundle 中存在 |
| `POST /delete` | 删除画布 | Bundle 中存在 |
| `POST /ops` | 以 revision 提交增量操作 | Bundle 中存在 |
| `POST /nodes/generate` | 提交节点生成 | Bundle 中存在 |
| `GET /nodes/runs` | 查询生成节点运行状态 | Bundle 中存在 |
| `GET /nodes/history` | 查询单节点生成历史 | Bundle 中存在 |
| `GET /nodes/studio3d/document` | 读取 3D 导演台独立文档 | Bundle 中存在 |
| `PUT /nodes/studio3d/document` | 保存 3D 导演台独立文档 | Bundle 中存在 |

证据集中于 `index.pretty.js:9462-9524`。

### 4.2 画布文档

当前画布 schema 常量为 `1.1.0`。详情响应会被整理成：

```text
canvas_document
├── schema_version
├── id / project_id / title
├── created_at / updated_at
├── defaults
├── viewport: x / y / zoom
├── nodes[]
├── edges[]
└── groups[]
```

节点包含布局、输入/输出端口、业务数据、运行态与可选素材绑定；边用 source/target 的 node_id 与 port_id 表达。

### 4.3 增量操作

Bundle 明确创建和压缩以下 operation：

| Operation | 作用 |
| --- | --- |
| `node.upsert` | 新增或更新完整节点 |
| `node.delete` | 删除节点 |
| `edge.add` | 新增连线 |
| `edge.delete` | 删除连线 |
| `canvas.update_meta` | 更新 viewport、defaults、groups 等画布元数据 |

证据：`index.pretty.js:9811-9882`、`InfiniteCanvasView.pretty.js:36084-36135`。

默认约 800ms 合并提交，服务端返回新 revision。请求失败时使用 3、8、20、45、60 秒退避序列继续提交。

### 4.4 缓存、离线与冲突

Bundle 中存在 IndexedDB，并缓存：

- `canvas_document`
- `revision`
- `dirty`
- `pending_ops`
- `last_server_revision`

网络失败时会优先载入磁盘中的未同步副本，其次使用内存副本。当前画布发生 409 revision 冲突时，代码会：

1. 丢弃当前画布尚未提交的 ops。
2. 显示“画布已被其他用户修改，请刷新后重试”。
3. 记录实际服务端 revision。

所以它是带离线队列和乐观锁的单文档同步，不是已经证实的实时多人协作。对非当前画布的冲突，操作会重新写回其 `pending_ops`。

### 4.5 生成任务恢复

所有主要生成入口最终都调用 `/nodes/generate`；前端每 3 秒通过 `/nodes/runs` 查询运行态。Bundle 中有 `resumeGeneratingNodes`，可把文档内仍为 generating 的节点重新加入轮询。

已确认走该链路的类型包括：

- 文本。
- 图片。
- 视频。
- 音频。
- 3D 模型。
- 故事版及图片/视频派生生成。

轮询连续失败达到阈值后会把节点置为失败，而不是永久显示生成中。这里确认的是前端提交与恢复设计，未用真实生成服务做端到端验证。

## 6. 生成器行为

### 6.1 引用与模型能力校验

生成器可读取上游连线和手工选择的引用节点，并按模型 `param_schema` 校验：

- 参考图片的最小/最大数量。
- 参考视频的最小/最大数量。
- 参考音频的最小/最大数量和总时长。
- 模型是否支持对应媒体输入。
- 必填字段、模式与计费规格。

提示词中支持图片、视频、音频 mention；生成历史会保存和展示提示词、模型、参数及参考媒体。

文本节点的模型选择器已在运行时打开，确认当前 UI 按多类文本模型提供选择。模型的完整名称和可用性会随当前账号服务配置变化，本文不把一次账号下的模型清单固化为产品能力。

### 6.2 图片生成

运行时已验证图片节点包含三条创作入口：

- 普通生成。
- 聚焦。
- 故事版。

普通图片生成配置提供 `1K / 2K / 4K` 三档分辨率、六种画面比例，以及低/中/高三档质量。六种比例的入口数量已核对，但本次证据没有稳定记录全部比例文本，因此不在本文猜测补全具体枚举。

故事版的时长与连续分镜提示见 6.4。本次只读探索没有提交图片或故事版生成，不能据配置态声称外部模型一定成功返回对应数量和质量的图片。

### 6.3 视频生成

视频生成包含两种明确模式：

- “全能参考”：允许参考图、参考视频等多模态参数。
- “首尾帧”：将图片分别映射到首帧和尾帧，并禁止参考视频。

这两种模式已在运行时切换验证。当前配置面板还确认：

- 分辨率：`480p / 720p / 1080p / 4K`。
- 时长：4–15 秒。
- 比例：`16:9 / 9:16 / 21:9`。
- 可选有声视频。

Bundle 会根据模型 schema 判断首帧、尾帧是否可用以及引用数量是否合法，不是只依赖固定前端文案。本次没有提交视频生成任务。

### 6.4 故事版

故事版入口文案为：

> 描述一个 10-15 秒内能演完的小剧情片段，系统会整理为 4-8 个连续分镜，内容过长时会自动提炼关键剧情。

故事版使用独立 `canvas_storyboard` 业务类型并进入持久节点生成/轮询链。入口、时长说明和分镜数量说明已在运行时验证；服务端实际是否返回 4–8 张合格连续分镜仍未做写入验证。

### 6.5 音频

音频生成器包含三种模式：

- 音乐：曲风、情绪和时长。
- 音效：自然、UI 反馈、拟音、怪物、机械等类型。
- 配音：多种男女声、童声、长者嗓音。

音频结果仍由节点运行态保存，空白音频节点入口被禁用并不等于音频生成逻辑缺失。

### 6.6 3D 模型

FrameOS 模型 store 会并行加载：

```text
toolbox_image
toolbox_video
toolbox_omni
toolbox_bgm
toolbox_3d
```

3D 生成完成时会读取模型结果 URL 与缩略图，再写回逻辑 3D 节点。运行时已打开真实 3D 生成配置，确认当前界面提供：

- 模型：`帧界 3D 1.0`。
- 面数偏好：标准、低模。
- 生成贴图开关。
- 姿势：无、A、T。

由静态链路和运行时配置可以确认原版确有真正的 3D 模型生成，而非只有 GLB 上传。因未提交生成任务，模型服务成功、文件格式与结果质量仍未验证。

| 拖动画布 | Space + 左键；中键或右键拖动 |
| 触控板 | 双指平移、捏合缩放 |
| 复制拖拽 | Alt/Option + 拖动 |
| 方向键移动节点 | 默认 5px；Shift + 方向键为 50px |

以上是帮助面板和键盘处理器的静态映射；浏览器/Electron 实际事件冲突尚未验证。

## 10. 3D 导演台证据

3D 导演台不是简单 GLB 预览器。本轮已实际进入编辑器并核对主要面板；静态 bundle 继续用于补足不适合在云端执行的写入和快捷键链路。

运行时已验证：

- 导演视角与机位视角。
- 场景树，以及隐藏、锁定、删除入口。
- 素体、素材库模型、群众阵列、几何体入口。
- 12 个固定机位预设，以及 1 个“保存当前导演视角”入口。
- `Auto / 21:9 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16` 七种截图比例。
- 20 种角色姿势和关节微调入口。
- 全景背景、天空、网格和地面设置。
- 当前机位截图与导演视角截图入口。

为遵守只读原则，没有新增/删除场景对象、保存场景、上传模型、生成截图或把截图发送回画布。

### 10.1 视图和控制

- 导演视角与机位视角切换。
- V/R/S 对应移动、旋转、缩放工具。
- 有选中对象时，WASD/QE 移动物体；无选中对象时移动或升降导演视角。
- 选中机位后可拖动调整位置。
- Esc 退出导演台。

### 10.2 场景树与对象

- 场景树搜索、选中和右键菜单。
- 显示/隐藏、锁定/解锁、复制和删除。
- 本地 GLB 上传和素材库模型。
- 内置素体变体、群众阵列和几何体。
- 群众可设置行、列和间距，并支持组级操作。
- GLTF 模型可标记为素体吸附目标。
- 骨骼只部分匹配时显示兼容性提示，无骨骼模型不开放关节微调。

### 10.3 环境、姿势和机位

- 场景整体缩放、平移、旋转。
- 全景本地上传或素材库选择。
- 天空颜色、全景水平旋转和全景球半径。
- 角色标签、网格吸附、地面显示、透明度和高度。
- 角色姿势预设和关节轴微调。
- 当前 bundle 的固定机位数组 `Wu` 明确为 12 项：正面中景、正面特写、正面全景、侧面跟拍、侧面近景、45°俯拍、低角度仰拍、低角度广角、左右过肩、鸟瞰和荷兰角；界面另有 1 个“保存当前导演视角”入口。此前把 12 个预设与保存入口合计为 13 个“预设”，现已纠正。
- 相机位置、旋转、手动注视坐标或目标模型、FOV；荷兰角预设包含 roll。

### 10.4 截图与回传

- 导演视角截图会自动创建机位。
- 当前机位截图和全部机位截图。
- 截图比例选择；运行时确认 `Auto / 21:9 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16`。
- 截图先保存在导演台文档的 `captured_shots` 中。
- 可多选截图并“发送到画布”。
- 发送成功后显示实际成功/失败数量。

### 10.5 独立文档与冲突

3D 场景文档含 `schema_version`、instances、shot_cameras、director_camera、environment、captured_shots 等字段。它通过独立 API 保存并拥有自己的 revision。

409 时 UI 文案要求“采用服务端并重新合并”，并明确警告同一导演台被另一标签页修改。该设计仍是 revision 冲突恢复，不是实时协同编辑。

上述列入“运行时已验证”的项目已经实际打开或观察到入口；复制、对象变换、上传、保存、全部机位截图、截图暂存和多选回传等会改变文档或产生素材的链路仅由 Bundle 证明，本次写入未验证。

## 13. 后续 1:1 验证清单

当前 FrameOS 画布已恢复正常渲染。剩余验证重点不再是等待 `Xi` 异常修复，而是需要在隔离测试数据或获得明确写入授权后补齐以下端到端证据：

1. 新建、切换、重命名和删除测试画布，记录真实空态、成功态和错误态。
2. 对每类节点验证创建、上传、生成、重试、刷新恢复和历史选用的真实结果。
3. 对所有引用组合验证模型能力限制和错误文案。
4. 验证连线落空创建、无效连接、复制/粘贴、Alt 拖拽、组与自动布局。
5. 确认其他 FrameOS 构建或账号是否下发不同 bundle；当前这份 bundle 的 `xq` 是常量 `false`，不能在运行时由普通远端配置改写。
6. 在网络断开、重连和双标签 revision 冲突下验证实际数据结果。
7. 完整走通 3D 模型生成、导演台编辑、当前/全部机位截图和多选回传。
8. 截图并记录每个面板的实际尺寸、动画、焦点、键盘和触控板行为。
9. 将每个已成功动作映射到 NoriVideo 的前端入口、API、持久化和权限测试。

当前准确表述是：FrameOS 原版画布的主要配置面板和 3D 导演台已有运行时基线，NoriVideo 也已有覆盖大部分静态能力的实现；但会改变云端数据的操作、真实生成结果和若干深层交互尚未完成原版端到端验证，仍不能宣称“所有子功能已经 1:1 复刻完成”。
