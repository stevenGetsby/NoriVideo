# LanmiaoTV 大画布流畅度设计

**交接范围：** 本文定义目标、设计和不变量；实施顺序见 [`2026-11-21-large-canvas-performance.md`](../superpowers/plans/2026-11-21-large-canvas-performance.md)。本次只做诊断和方案，不含代码改动或生产发布授权。

## 1. 目标：总量增长，单次交互的成本不跟着增长

用户可以保留全部素材、节点、连线和生成历史，不靠删素材或拆旧画布解决卡顿。打开画布时先显示可操作的首屏；平移、缩放和拖节点时，只花钱处理当前视野里有用的内容；全局缩览仍应能定位节点、组和剧情。素材库里存的项与摆上画布的节点是两种规模，分别治理，不把它们混成同一个问题。

不能承诺任意设备上无限数量、无限细节同时以 60 FPS 渲染。可验收的工程目标是：**DOM 节点、交互边、媒体解码、每次请求和每帧计算有明确预算；超预算自动切换到可定位、可选择的概览，不丢内容。** 现有代码的 1,000 节点、4,000 边及完整文档 16 MiB 是兼容性护栏，不是性能方案。先把当前上限内做顺；超过上限要等分块读取、保存和恢复全链路过验收，再独立提高额度。不要只改三个数字。

## 2. 根因与证据

2026-11-21 备案机只读统计，项目「老头影游_马俊」：

| 主画布 | 节点（视频） | 连线 | 画布 GET 200 响应体中位数（Nginx 实际发送） |
|---|---:|---:|---:|
| 第一部分 | 179（108） | 1,111 | 2,001,879 B（62 次） |
| 第三部分 | 176（126） | 724 | 395,770 B（168 次） |
| 第二部分 | 46（23） | 91 | 85,254 B（50 次） |

- **打开、重载慢：** 第一部分节点 `data` 约 9.9 MiB，其中约 7.6 MiB 是视频生成历史。640 条历史里，提示词约 5.6 MiB，引用明细约 1.6 MiB；这些不是首屏媒体文件。当前 GET 全量读取、清洗、序列化和计算 ETag。命中 304 也不等于省了前面的工作。节点 `data` 的数据库字节数与 Nginx 响应字节数不是同一口径。
- **交互中：** 第一部分 1,111 条边没有完全重复边或悬空端点；不能靠清理异常数据解决。同一张合成图 179 节点，仅将边从 198 提高到 1,111，Chrome/M4 平移主线程工作累计由 296–326 ms 增至 489 ms（88 步，约 +57%）；未在该设备复现掉帧。当前 `onlyRenderVisibleElements` 已开启，但可见边选择器仍扫描 React Flow 收到的边，并为可见边挂载 SVG。远景时大量卡片也会在同一视野内；仅开启视口裁剪不够。旧合成脚本的程序化缩放结果不作为验收证据，必须验证实际 React Flow transform 改变。
- **停手、编辑时：** 纯视角变化会触发通用保存；虽然网络使用 `/ops` delta，客户端仍构造文档、全图序列化比较，服务端事务仍读取整图，并按策略记整图快照。撤销栈还对整个对象图 `structuredClone`，最多 80 条。合成数据 179 节点／1,111 边，只改视角，Chrome 4× CPU 降速下 `buildCanvasOperations` 中位数从 11.9 ms 增至 46.3 ms（加约 7.5 MB 历史）；单次撤销克隆中位数从 2.1 ms 增至 21.9 ms。不是线上用户设备的实测帧率。
- **素材面板是次要、独立的热点：** `CanvasProjectAssets` 会拉完分页并挂载完整列表；`MaterialPickerDialog` 某些查询也会拉剩余页。优化它能解决打开面板和搜索卡，不会替代主画布优化。既有海报优先、缩略图、缩放档位与节点 memo 继续复用。

服务器在采样时没有明显负载压力，但这不能排除高峰后的网络或数据库影响。不把换服务器、调 Nginx 或换绘制引擎当作第一步。上线后用请求耗时和浏览器 trace 分开验收。

## 3. 选定架构与取舍

1. **只做 CSS 隐藏、调 memo 或阈值：** 改动小，但画布仍全量读、比较、订阅和挂载。不选为最终方案。
2. **在现有 React Flow 上分离权威图、渲染投影和按需详情（采用）：** 编辑语义不变。通过视口索引和预算减少浏览器工作量；大图保存改为操作，详情不进入热路径；素材面板独立分页。保留现有交互、权限和回退路径。
3. **全量迁移 Canvas/WebGL：** 可以增加绘制吞吐量，但本身不解决请求、历史或保存；会重写命中、端口、文本、键盘和无障碍。先用一个 Canvas 2D 概览层；只有实测证明它仍过不了预算，才另立渲染项目。

| 层 | 职责 | 绝不能做的事 |
|---|---|---|
| 权威图／命令层 | 节点与边 ID、引用方向/角色、选择、编辑、生成和持久化。第一阶段可保留当前完整拓扑，长线用分块存储及远程查询。 | 用“屏幕上没看到”推导删除或取消引用。 |
| 渲染投影 | 根据视口、缩放、手势和选择挂载少量完整卡片与交互边；超出预算画聚合概览，选中后可展开/搜索。 | 把投影写回权威图，或在停手时无上限恢复全部 SVG。 |
| 详情层 | 历史、长提示词、引用明细、仅特定编辑器需要的重字段。按节点与版本读取，缓存独立受限。 | 把未加载当作 `[]`／`null` 写回，或让迟到响应覆盖本地草稿。 |

## 4. 不变量与验收

- 所有优化只改变读取、渲染和保存成本；**不删素材、不删连线、不截断生成引用或历史、不改变计费与权限**。普通 `INPUT_DEFAULT` 素材线可简化为概览；保留影游 `STORY_FLOW`、挂载和画面引用的语义及常规编辑状态可见性。未来影游若也需分块或聚合，另加剧情拓扑验收后打开，不跟普通画布一起默认灰度。
- 缩到很远时可显示素材/组计数和可搜索列表；选中、聚焦、连接、键盘及框选明确作用到什么。允许少画，不允许少选、连错、保存错。连线超过视觉预算可在完整列表逐条查找、定位、解除，不伪装成“没有连线”。
- 已打开旧页面、离线草稿、多标签冲突、异步生成回写、项目/画布权限、任务/素材链接、撤销及服务端历史恢复继续正确。新读取视图不是用于完整保存的文档，类型和接口层都要挡住误用。
- 第一批必须报告 179/1,111 真实比例替身与 1,000/4,000 当前上限的同机前后对比；后续扩容门槛 5,000/20,000，先合成测试，非当前承诺。精确负载、上限、性能目标与发布顺序见实施计划。日志、测试数据和 trace 不携带真实提示词、用户身份、媒体 URL 或鉴权信息。
