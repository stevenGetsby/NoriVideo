# 项目管理交互与资产批量上传

仅本地修改，未部署；不修改生产账号、余额、密钥和现有资产。

## 项目管理

- 项目卡片右上角菜单常驻可见，点击打开，不再因悬停打开后被同一次点击关闭。
- 使用视口浮层，避免被卡片、滚动容器或 120% 界面缩放截断。
- 管理账号可编辑名称、简介、画风、比例、分辨率、时长及业务模型。
- 项目内头部也提供编辑、重命名、删除；保存后刷新项目名称与配置缓存。
- 删除仍为移入回收站，保留原有 15 天恢复期。
- 前端角色判断和后台 `requireProjectManager` 双重限制：只有
  `admin/super_admin` 可编辑、重命名、删除。创建者身份、协作者权限、
  旧账号 `actorId === workspaceOwnerId` 都不能替代管理员角色。
- 名称/简介与生成配置使用原有两条接口；部分保存失败会明确提示并保留
  弹窗，允许重试，不假报全部成功，不重新导入剧本。

## 批量上传与目录修复

- 资产库和素材库支持多选文件，每批最多 100 个，单文件沿用 200MB 限制。
- 文件名自动作为素材名，可逐项编辑；逐张显示待上传、上传中、成功、失败。
- 单文件串行请求复用原上传接口，避免大量图片同时解码；单张失败不阻断后续。
- 重试仅提交未成功项，不再次提交明确成功的文件；上传中禁止关闭或更改归属。
- 从资产目录发起上传时锁定项目与角色/场景/道具分类，关闭再打开会读取新目录。
- 项目目录展开独立的角色、物品、环境子目录，全局目录不会沿用项目归属。
- 资产请求携带具体 `kind`，后台只读取相应分类，不让损坏的角色记录阻断场景读取。
- 取消旧目录请求，并按账号、项目、分类标记响应和当前展示，防止旧响应、旧警告
  覆盖新目录。结构化资产/上传素材部分失败时另一部分仍可浏览和上传。
- 无 MIME 或通用 MIME 的常见图片按扩展名进入 Sharp 验证、规范化，不绕过
  文件大小、图片解码、像素数量或存储权限校验。
- 批量列表 ID 在 HTTP/IP 访问、缺少 `crypto.randomUUID` 时仍可生成。
- 弹窗独立于工作区缩放，内容内部滚动，标题、关闭和底部按钮始终可见。
