# 项目与作品层级纠正

业务层级统一为：

```text
项目
└─ 作品
   ├─ 剧集、剧本、分镜与视频
   ├─ 角色、场景、道具与音色
   └─ 无限画布、生成任务与用量
```

## 用户交互

- 首页及侧栏为“我的项目”，上层按钮为“新建项目”。
- 项目面板展示其作品数量，在项目内“新建作品”，弹窗明确显示“所属项目”。
- 作品保留独立的风格、模型、剧本、素材、画布及计费归属。
- 作品可编辑、重命名、移动到其他项目；删除作品进入 15 天回收站。
- 参与人员可编辑作品，项目管理、删除及移动继续受既有管理员权限约束。
- 任务筛选、资产与素材归属、画布面包屑、用量报表和导出统一使用正确名称。
- 小屏自动收起侧栏；手动展开采用浮层，不把内容压缩成窄条。项目标题、
  新建和回收站按钮可换行排列，按钮文字不折成错位的多行。

## 数据兼容

旧实现中的名称正好相反：`Work` 表保存上层容器、`Project` 表保存实际生产单元。
本次不删除、重新创建或交换历史记录，不改 ID 和外键；通过
`src/lib/projects/hierarchy.ts` 显式映射业务语义：

- 旧 `Work` → 项目。
- 旧 `Project` → 项目内作品。
- 新 `projectHierarchy.version = 2` 返回项目数组及各项目的作品。
- 作品创建接受 `parentProjectId`，移动接受 `workIds` / `targetProjectId`，
  旧请求字段仍兼容；互相冲突的父项目参数明确拒绝。
- 工作台详情增加 `parentProject`，作品的任务、素材、画布和账单继续使用原 ID。
- 旧接口 URL、缓存键和持久化画风提示词标记保留，避免破坏历史任务或草稿。
- Prisma 对新旧结构比较为空迁移，不需要导入数据库快照或重建数据。

额外修复：项目下仍有回收站作品时禁止删除项目。删除条件在数据库层再次
判断“无任何作品”，避免失去恢复父级或遇到外键失败。
